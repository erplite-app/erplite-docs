Filtering and search help users move from a large table to the records that need attention.

## Search

Use search for quick text lookup across recognizable record fields. Search is best for:

- Record numbers.
- Names.
- Customer, vendor, or asset labels.
- Short text values.

For structured conditions such as status, team, date, or empty fields, use filters instead.

## Filters

Filters are field-specific conditions. Common examples:

| Need | Filter |
|------|--------|
| Show open work | Status equals Open |
| Show overdue items | Due Date before Today |
| Show records without owner | Owner is empty |
| Show records assigned to the current user | Assignee equals Current User |
| Show records for the user's team | Team equals Current Team |
| Show records matching any of several statuses | Status is one of selected values |
| Show completed work this week | Completed Date is in the desired range |

Filters can be combined using **AND** or **OR**, depending on whether all conditions or any condition should match.

## Sorting

Sort records by fields such as expected delivery date, priority, updated date, amount, status, or owner. Multiple sort rules can be stacked when a table needs a stable operating order.

## Filter Chips

Active filters appear as chips so users can quickly see what is affecting the current list. Remove chips to broaden the results.

## AI Guidance

### When to Use This Feature

An AI should use filters when the user asks for a subset of records, a saved queue, a dashboard widget, or a report based on field values.

Use search only when the user gives a keyword or identifier. Use filters when the user gives business conditions.

### How to Use It

<Steps>
  <Step title="Translate the request into field conditions">
    For example, "late dispatches" might mean Status is not Delivered and Expected Delivery Date is before today.
  </Step>
  <Step title="Choose AND or OR">
    Use **AND** when all conditions must be true. Use **OR** when any condition can qualify the record.
  </Step>
  <Step title="Use dynamic tokens when needed">
    Use **Current User** or **Current Team** for reusable views that should behave differently for each signed-in user.
  </Step>
  <Step title="Sort the result">
    Put the most urgent records first, such as oldest due date or highest priority.
  </Step>
  <Step title="Save as a view if reused">
    Save the filtered result as a view when users need it repeatedly.
  </Step>
</Steps>

### How to Verify

The AI should verify:

- Records that should match are included.
- Records that should not match are excluded.
- Empty/not-empty filters behave correctly.
- Date filters match the intended business date.
- Dynamic user/team filters work for more than one user.
- Saved views preserve the filter and sort behavior.

## Best Practices

- Use filter names that match business language.
- Prefer saved views for repeated filters.
- Test exception views with known positive and negative sample records.
- Use dynamic filters for "my work" views instead of creating one view per person.
