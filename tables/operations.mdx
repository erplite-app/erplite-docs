Table operations are administrative actions that affect the table itself, not just individual records.

## Common Operations

| Operation | Use It For | Verify By |
|-----------|------------|-----------|
| **Create table** | Add a new business record type. | The table appears in navigation and can create a sample record. |
| **Rename table** | Improve the user-facing name. | Existing records, views, relations, and automations still work. |
| **Duplicate table** | Start a similar table from an existing schema. | The copy has the expected columns and permissions are reviewed. |
| **Delete table** | Remove a table that should no longer exist. | Confirm no active process, report, automation, or relation depends on it. |
| **Refresh** | Reload latest records after imports or automations. | New or changed records appear. |
| **Table settings** | Manage columns, permissions, display, and behavior. | Changes are visible to the intended users. |
| **Export CSV** | Download records for review or reconciliation. | Exported rows match the current filters or table state. |
| **Import CSV / Excel** | Create or update many records. | Result CSV and sample records confirm the import. |

## AI Guidance

### When to Use This Feature

An AI should use table operations when the workspace structure itself needs to change. For example:

- A new process needs its own table.
- A table name is confusing users.
- A similar table is needed for another department.
- A table was created during testing and should be removed before go-live.
- Data changed in the background and the screen needs refresh.

### How to Use It

<Steps>
  <Step title="Confirm the purpose">
    Ask what business outcome the table operation supports.
  </Step>
  <Step title="Check dependencies">
    Review relations, views, workflows, automations, reports, imports, and permissions before renaming, duplicating, or deleting.
  </Step>
  <Step title="Make the change">
    Use the table toolbar or table settings for the required operation.
  </Step>
  <Step title="Verify with records">
    Create, open, search, or export a sample record to confirm the table still behaves correctly.
  </Step>
</Steps>

### How to Verify

The AI should verify:

- The table is visible to intended users.
- Existing views still load.
- Relation fields that point to or from the table still display readable records.
- Workflow actions still appear where expected.
- Automations referencing the table still run.
- Reports and home widgets using the table still show data.

<Warning>
Before deleting a table, confirm with the business owner. Deleting a table can remove records, break relations, disable reports, and invalidate automations.
</Warning>
