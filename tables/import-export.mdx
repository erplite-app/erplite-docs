ERPLite supports imports and exports so teams can move operational data in and out of tables safely.

Imports support two common business flows:

| Mode | Use It For |
|------|------------|
| **Add New** | Creating new records from a CSV or Excel file. |
| **Update Existing** | Updating existing records in bulk without recreating them. |

Exports produce CSV files that can be used for audits, offline review, reconciliation, or as templates for update imports.

## Import Flow

<Steps>
  <Step title="Open the table">
    Go to the table you want to import into.
  </Step>
  <Step title="Choose Import CSV / Excel">
    Open the table actions menu and select **Import CSV / Excel**.
  </Step>
  <Step title="Choose Add New or Update Existing">
    Use **Add New** for new records and **Update Existing** when rows should change records already in ERPLite.
  </Step>
  <Step title="Upload a file">
    Upload a CSV or Excel file. Keep each import to a practical row count so errors are easy to review.
  </Step>
  <Step title="Map columns">
    Match file columns to ERPLite fields. ERPLite suggests matches based on names.
  </Step>
  <Step title="Map option values">
    For dropdown, status, choice, or multi-choice fields, confirm file values map to valid ERPLite options.
  </Step>
  <Step title="Validate">
    Review errors before import. Fix missing required fields, invalid formats, relation mismatches, and duplicate rows.
  </Step>
  <Step title="Confirm import">
    Enter the email address that should receive the result file, then run the import.
  </Step>
</Steps>

## Supported Data Patterns

| Field Type | Import Guidance |
|------------|-----------------|
| **Text** | Use plain text. |
| **Numbers, currency, percent** | Use numeric values without extra labels. |
| **Dates** | Use a consistent date format in the file. |
| **Dropdown/status/choice** | Values must match or be mapped to configured options. |
| **Relations** | Use readable related record names or identifiers that can be matched. |
| **Users/teams** | Use values that clearly identify the user or team. |
| **Files/images** | Use accessible URLs where file/image import is supported. |

## Update Existing Records

Use update imports when the records already exist and a spreadsheet contains changes. The import should include a reliable way to match each row to the existing record, such as an ID, record number, or another agreed unique value.

Update imports are useful for:

- Updating expected delivery dates.
- Correcting pricing or quantities.
- Updating statuses from an external reconciliation file.
- Filling missing fields after initial migration.

## Import Results

Large or partial imports can continue in the background. ERPLite sends a result CSV to the chosen email address so the user can see which rows succeeded, which failed, and why.

## AI Guidance

### When to Use This Feature

An AI should use import when:

- Initial setup requires many records.
- Business users provide master data in spreadsheets.
- Existing records need bulk correction.
- A recurring process exports data from another system and loads it into ERPLite.

An AI should avoid import when there are only a few records and manual creation is faster and easier to verify.

### How to Use It

1. Ask the user whether the file should **create** or **update** records.
2. Confirm the target table.
3. Review the file headers before upload.
4. Map each file column to an ERPLite field.
5. Resolve option values and relation matches.
6. Run validation.
7. Fix errors before confirming.
8. Confirm the result email.
9. Review the result CSV after import.

### How to Verify

The AI should verify:

- The imported row count matches the expected count.
- Failed rows have clear reasons and are not silently ignored.
- Relation fields link to the correct records.
- Dropdown/status values use valid options.
- File/image URL fields render as attachments or previews where applicable.
- Update imports changed the intended existing records and did not create duplicates.
- Views and reports that depend on the imported data now show correct results.

<Warning>
Do not run a bulk update import until the matching field is clear. If matching is ambiguous, create a small test import first and verify the exact records that changed.
</Warning>
