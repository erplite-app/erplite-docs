## Overview

ERPLite supports bulk data operations through CSV import and export, making it easy to migrate data, perform bulk updates, or create backups.

---

## Importing Data

Import records from a CSV file into your table.

### Getting the Template

Before importing, download the CSV template to ensure your data matches the table structure.

<Steps>
  <Step title="Open Import Menu">
    Click the **More Options** menu (three dots) in the table toolbar
  </Step>
  <Step title="Download Template">
    Click **Download Template** to get a CSV file with column headers matching your table
  </Step>
  <Step title="Fill in Data">
    Open the template in Excel/Google Sheets and add your data
  </Step>
</Steps>

### Template Structure

The template includes headers for each column in your table:

```csv
name,email,phone,status,created_date
John Doe,john@example.com,555-0100,Active,2024-01-15
Jane Smith,jane@example.com,555-0101,Pending,2024-01-16
```

<Note>
Column headers must match exactly. Use the downloaded template to ensure compatibility.
</Note>

### Importing the File

<Steps>
  <Step title="Open Import">
    Click the **More Options** menu and select **Import**
  </Step>
  <Step title="Select File">
    Click **Select File** and choose your CSV file
  </Step>
  <Step title="Select Header Row">
    Specify which row contains your column headers (usually row 1)
  </Step>
  <Step title="Map Columns">
    Map CSV columns to table columns. The system auto-maps matching names.
  </Step>
  <Step title="Validate Data">
    Review any validation errors:
    - **Red rows**: Data doesn't match column type
    - Fix errors or click **Discard Selected Rows** to skip them
  </Step>
  <Step title="Complete Import">
    Click **Confirm** to import the validated records
  </Step>
</Steps>

### Field Format Reference

Every column type expects a specific cell format. Use this table when preparing your file — getting the format right up front avoids validation errors.

| Column Type | Expected Format | Example | Empty cell |
|-------------|-----------------|---------|------------|
| Text / Textarea | Plain text | `John Doe` | Cleared (left blank) |
| Number / Currency / Percent | A number only — no symbols, no thousands separators | `1234.50` (not `$1,234.50`) | Cleared |
| Boolean | `true`/`false`, `yes`/`no`, or `1`/`0` | `true` | Cleared |
| Date | `YYYY-MM-DD` | `2024-01-15` | Cleared |
| DateTime | ISO 8601 | `2024-01-15T10:30:00` | Cleared |
| Email | A valid email address | `john@example.com` | Cleared |
| Phone | Plain text (digits, `+`, spaces) | `+1 555 0100` | Cleared |
| URL | A single valid URL (includes `https://`) | `https://acme.com` | Cleared |
| Choice | Exact option text (case-sensitive) | `Pending` | Cleared |
| Multi-Select | Comma-separated option text | `Tag1, Tag2, Tag3` | Cleared |
| List of Text | Comma-separated values | `item1, item2, item3` | Cleared |
| Location | `address, lat, long` | `123 Main St, 37.77, -122.41` | Cleared |
| **File / Image** | **One URL, or several URLs separated by commas** | `https://cdn.acme.com/a.pdf` or `https://cdn.acme.com/a.pdf, https://cdn.acme.com/b.pdf` | **Set to empty (no file)** |
| **Relation** | **The target record's display name, or its record ID** | `Acme Corp` or `rec_abc123` | Cleared (link removed) |
| User / Team | The user/team's name (resolution is best-effort — use the ID if a name doesn't resolve) | `Priya Sharma` | Cleared |

<Note>
Computed, button, and signature columns are read-only on import — values in those columns are ignored.
</Note>

### Import Tips

<AccordionGroup>
  <Accordion title="File & Image fields (URLs)">
    File and image columns store **URLs**, and a record can hold more than one.

    - **One file**: put a single URL in the cell — `https://cdn.acme.com/invoice.pdf`
    - **Multiple files**: separate the URLs with commas — `https://cdn.acme.com/a.pdf, https://cdn.acme.com/b.pdf`
    - **No file**: leave the cell empty — the field is stored as empty (it will not error)

    Each value must be a valid URL (starting with `http://` or `https://`). A value that isn't a URL is flagged on the row.
  </Accordion>

  <Accordion title="Relation fields (name vs. record ID)">
    A relation cell can be either:

    - the target record's **display name** (e.g. `Acme Corp`), or
    - its **record ID** (e.g. `rec_abc123`).

    For a **multi-link** relation, separate several values with commas: `Acme Corp, Globex`.

    If a display name matches **more than one** record, the importer can't tell which one you mean. It will ask you to **use the record ID** for that cell instead — the record ID is always unique. (Tip: export the related table first to get each record's ID.)
  </Accordion>

  <Accordion title="Handling Date Formats">
    Dates should be in `YYYY-MM-DD` format. Other formats may cause validation errors.
  </Accordion>

  <Accordion title="Location Fields">
    For location fields, provide address, latitude, and longitude separated by commas:
    `123 Main St, 37.7749, -122.4194`
  </Accordion>

  <Accordion title="Choice Fields">
    Values must exactly match one of the defined options (case-sensitive).
  </Accordion>
</AccordionGroup>

## Exporting Data

Export your table data to CSV for reporting, backup, or analysis.

<Steps>
  <Step title="Apply Filters (Optional)">
    Use filters to export only specific records
  </Step>
  <Step title="Open Export">
    Click the **More Options** menu and select **Export**
  </Step>
  <Step title="Download File">
    The CSV file downloads automatically
  </Step>
</Steps>

### Export Limits

<Warning>
Exports are limited to **1,000 records** at a time. For larger datasets:
1. Apply filters to narrow down the data
2. Export in batches
3. Or use the API for programmatic export without limits
</Warning>

### Exporting with Filters

To export a subset of your data:

1. Apply filters to show only the records you want
2. The export will only include visible (filtered) records
3. This also helps when you have more than 1,000 records

### Export Format

Exported CSV files include:
- All visible columns (hidden columns are excluded)
- Current filter state applied
- All data types converted to text representation

## For AI Agents

### API: Bulk Import Records

```bash
POST /zorp-tables-service/table/records
Authorization: Bearer {secretKey}
Content-Type: application/json

{
  "tableType": "my_table",
  "records": [
    {
      "data": {
        "name": "John Doe",
        "email": "john@example.com",
        "status": "Active"
      }
    },
    {
      "data": {
        "name": "Jane Smith",
        "email": "jane@example.com",
        "status": "Pending"
      }
    }
  ]
}
```

**Response:**
```json
{
  "code": "200",
  "message": "2 records created successfully",
  "data": {
    "created": 2,
    "failed": 0,
    "recordIds": ["rec_123", "rec_124"]
  }
}
```

### API: Export Records (Paginated)

```bash
POST /zorp-tables-service/table/search
Authorization: Bearer {secretKey}
Content-Type: application/json

{
  "tableTypes": ["my_table"],
  "page": 0,
  "size": 100,
  "filters": [],
  "sorting": []
}
```

**Response:**
```json
{
  "code": "200",
  "data": {
    "records": [...],
    "total": 1500,
    "page": 0,
    "size": 100
  }
}
```

### Batch Export Pattern

For exporting more than 1,000 records programmatically:

```javascript
async function exportAllRecords(tableType, secretKey) {
  const allRecords = [];
  let page = 0;
  const pageSize = 100;
  let hasMore = true;

  while (hasMore) {
    const response = await fetch('/zorp-tables-service/table/search', {
      method: 'POST',
      headers: {
        'Authorization': `Bearer ${secretKey}`,
        'Content-Type': 'application/json'
      },
      body: JSON.stringify({
        tableTypes: [tableType],
        page: page,
        size: pageSize
      })
    });

    const data = await response.json();
    allRecords.push(...data.data.records);

    hasMore = allRecords.length < data.data.total;
    page++;
  }

  return allRecords;
}
```

### Import Validation

The import process validates:
- **Type matching**: Values match column data types
- **Required fields**: All required columns have values
- **Choice validation**: Values match defined options
- **Relation validation**: Referenced records exist. A value that can't be matched to a record returns guidance to **use the record ID to disambiguate** (a display name may be missing or match more than one record).
- **File / Image normalization**: A single URL, a comma-separated list, or a JSON array of URLs is accepted and stored as an array; an empty cell is stored as empty (no error). Each value must be a valid URL.
