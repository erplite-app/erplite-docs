Sharing controls who can access a table and what they can do inside it. ERPLite uses permission sets so the same table can be shared differently with managers, operators, finance users, vendors, or administrators.

## How Sharing Works

1. A table has one or more **permission sets**.
2. Each permission set contains allowed actions.
3. Users, teams, or roles are assigned to a permission set.
4. ERPLite combines this with role-level and column-level permissions.

## Share a Table

<Steps>
  <Step title="Open the table">
    Go to the table you want to share.
  </Step>
  <Step title="Open table settings">
    Choose the table settings or sharing option.
  </Step>
  <Step title="Add collaborators">
    Select users, teams, or roles.
  </Step>
  <Step title="Choose a permission set">
    Assign the selected people to the correct access level.
  </Step>
  <Step title="Notify if needed">
    Choose whether to notify the people who now have access.
  </Step>
  <Step title="Save">
    Save changes to apply the sharing configuration.
  </Step>
</Steps>

## AI Guidance

### When to Use This Feature

An AI should configure sharing whenever a table is created, a new team needs access, or a user cannot see a table they should use.

Use table sharing for table-wide access. Use column permissions when only specific fields are sensitive.

### How to Use It

1. Identify who needs access: users, teams, or roles.
2. Decide what they need to do: view only, create records, edit records, comment, manage views, manage automations, or manage sharing.
3. Assign them to the appropriate permission set.
4. Create a new permission set only when existing sets do not match the business need.
5. Keep at least one trusted admin group with **Manage Sharing** access.

### How to Verify

The AI should verify:

- A user in the target team can see the table.
- The user can perform only the intended actions.
- A user outside the target group cannot see or modify the table.
- The table still has at least one permission set with **Manage Sharing** assigned.
- Sensitive columns are separately hidden or locked if table access alone is too broad.

<Warning>
Do not remove all users, teams, or roles that can manage sharing. If nobody has sharing access, administrators may need to restore it.
</Warning>
