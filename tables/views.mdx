Views are saved ways of looking at table records. A view can include filters, sorting, column visibility, column order, display mode, grouping, and access settings.

Use views to turn a large table into practical work queues.

## View Types

| View Type | Best For |
|-----------|----------|
| **Table view** | Detailed lists, search-heavy work, audits, exports, and bulk review. |
| **Kanban view** | Moving work by status, owner, priority, or stage. |
| **Grouped table view** | Reviewing records grouped by status, team, assignee, customer, vendor, or date bucket. |
| **System views** | Built-in views created by ERPLite for workflows or important operating states. |

## Common Business Views

- **My Open Work**

## AI Guidance

### When to Use This Feature

An AI should create a view when users repeatedly need the same filtered or grouped list. If a user asks, "Show me only..." or "I want a queue for...", a view is often the right answer.

Use a view instead of a new table when the records already belong in the same table but need a different lens.

### How to Use It

<Steps>
  <Step title="Open the table">
    Go to the table that contains the records.
  </Step>
  <Step title="Apply search, filters, and sort">
    Filter by status, owner, team, date, priority, relation, empty/not empty values, or other field types.
  </Step>
  <Step title="Choose display mode">
    Use table mode for detail, kanban for stage movement, or grouped mode for queue review.
  </Step>
  <Step title="Choose visible columns">
    Show only the columns users need for the job. Put important fields first.
  </Step>
  <Step title="Save the view">
    Give the view a short business name and configure who can access or manage it.
  </Step>
</Steps>

### How to Verify

The AI should verify:

- The view returns the expected sample records.
- Records that should not match are excluded.
- Sorting and grouping make sense for the user's workflow.
- Kanban lanes match the selected field values.
- The visible columns are enough to decide what to do next.
- A target user can access the view, and a non-target user cannot if restricted.
- Switching between views keeps the selected system or saved view active.

## Display Settings

Display settings let users choose:

- Table or kanban display.
- Group by field.
- Column order.
- Column visibility.
- Reset to default layout.

Column widths are saved locally so repeated users can keep comfortable table layouts.

## Filters and Dynamic Tokens

Views can use filters such as:

- Field equals a value.
- Field is empty or not empty.
- Date before or after.
- Multi-value filters.
- Current user.
- Current team.

Dynamic filters are useful for shared views such as **My Work**, where each user sees their own assigned records from the same view.

<Tip>
For AI setup, always test a shared dynamic view with at least two users or teams. A view that works for an admin may not prove it works for operators.
</Tip>
