Records are the individual business items stored inside a table. A Purchase Orders table contains purchase order records. An Assets table contains asset records. A Dispatches table contains dispatch records.

## What Users Can Do on Records

Depending on permissions and configuration, users can:

- Create new records.
- Edit fields.
- Search and filter records.
- Open record detail pages.
- Add comments and mentions.
- Review activity history.
- Read data from another system in a record widget.
- Upload files, images, and signatures.
- Link related records.
- Create or edit child records inline.
- Pull items from source records using document mappings.
- Move records through workflow actions.
- View allocation or rollup summaries.
- Delete records if allowed.

## Creating a Record

<Steps>
  <Step title="Open the table">
    Go to the table where the record belongs.
  </Step>
  <Step title="Click New">
    ERPLite opens a full-page create form.
  </Step>
  <Step title="Fill required fields">
    Required fields and conditional required fields must be completed before save.
  </Step>
  <Step title="Add related records">
    Use relation tabs to link existing records or create child records, depending on the relation setup.
  </Step>
  <Step title="Use Get Items From if available">
    If the table has a document mapping, pull header or line item data from the source record and review it before saving.
  </Step>
  <Step title="Create">
    Save the record. Auto-ID fields, derived fields, and workflow starting status are filled automatically where configured.
  </Step>
</Steps>

## Record Detail Page

The detail page shows:

| Area | Purpose |
|------|---------|
| **Header** | Record name, status, key metadata, and actions. |
| **Details** | Main field values arranged for review. |
| **Related tabs** | Child or linked records such as items, dispatches, invoices, or work orders. |
| **Workflow bar** | Status path and next available actions. |
| **Side column** | Tabs for **Widgets**, **Comments**, and **Activity**, on the right of the record. |
| **Widgets** | Data from another system for this record. See [Record Widgets](/configurations/record-widgets). |
| **Comments** | Team discussion and mentions. |
| **Activity log** | Audit trail of record changes. |
| **Allocation tab** | Read-only summary of how quantities have been allocated across downstream documents, when rollup fields exist. |

### The Side Column

On a screen 1024px or wider, the record page has a side column on the right.
The side column has these tabs:

- **Widgets**, when the record has a widget that the user can see.
- **Comments**.
- **Activity**.

The **Widgets**, **Comments**, and **Activity** buttons in the record header control the column:

- When the column is closed, a button opens it on that tab.
- When the column shows another tab, a button moves to its tab.
- When the column shows that button's tab, the button closes the column.

A closed column takes no space. The record fields use the full width.

On a screen 1440px or wider, the column opens on the Widgets tab when the record has a widget.
On a narrower screen, the column starts closed.

Below 1024px, there is no side column.
Comments and Activity open as panels over the page, and widgets appear under the workflow status bar.

### Small and Zoomed-In Screens

Many users work on laptops with display scaling, for example a 1366×768 screen at 125%.
On these screens the record page gives the fields more room:

- The record fields change from two columns to one column when the page is narrow.
- The side column starts closed.

## AI Guidance

### When to Use This Feature

An AI should create or edit sample records whenever it needs to verify a table, workflow, view, automation, report, import, or permission setup. A configuration is not complete until at least one realistic record proves it works.

### How to Use It

<Steps>
  <Step title="Create realistic sample data">
    Use values that match the business process, not placeholder text. Include dates, owners, teams, amounts, statuses, and relations.
  </Step>
  <Step title="Test the create form">
    Confirm the form shows only the fields users should fill and hides read-only fields such as auto-ID and derived fields.
  </Step>
  <Step title="Test edits">
    Change normal fields, restricted fields, relation fields, and conditional fields to confirm the expected behavior.
  </Step>
  <Step title="Test related records">
    Add or link child records and confirm they appear on the parent record and in the child table.
  </Step>
  <Step title="Test workflow actions">
    Run available record actions and confirm status, derived values, related records, and automation results update.
  </Step>
</Steps>

### How to Verify

The AI should verify:

- Required and conditional required fields block incomplete saves.
- Auto-ID fields are generated without manual entry.
- Derived fields show preview or saved calculated values and cannot be edited directly.
- Relation fields display readable names.
- Inline child rows save with the parent or existing record as expected.
- Comments and activity logs capture meaningful history.
- On a 1366×768 laptop at 125% scaling, the record fields are readable, and the side column buttons open and close the column.
- Users see only the records and actions allowed by permissions.
- Allocation or rollup tabs match the linked child records.

## Best Practices

- Use one record per real business item.
- Keep identifiers stable, such as PO Number, SO Number, Asset ID, or Work Order Number.
- Prefer relations over copy-pasting values from another table.
- Use comments for collaboration, not for data that should be a structured field.
- Use activity history when investigating who changed a record and when.
