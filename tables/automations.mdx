Automations run repeatable business logic so users do not need to remember every follow-up step. They can send messages, update records, create related records, call external systems, search records, or run custom logic.

Automations are available under **Configurations > Automations** and can also be tied to table and workflow behavior.

## When to Use Automations

Use automations when the business says:

- "When this record is created, notify someone."
- "When status changes, update a related record."
- "Every day, check for overdue work."
- "When a webhook arrives, create or update records."
- "Send an email or Slack message when a threshold is crossed."
- "Generate follow-up records automatically."
- "Block saves unless a rule is satisfied."
- "Call an external system after approval."

Do not automate a process until the manual process is clear. First make the table, fields, views, permissions, and workflow actions work for sample records.

## Trigger Types

| Trigger | Use It For |
|---------|------------|
| **Record created** | Run when a new record is added to a table. |
| **Record updated** | Run when an existing record changes. |
| **Record deleted** | Run cleanup or notification logic after deletion. |
| **User created/deleted** | React to account-level user changes. |
| **Team assignment changes** | React when users are assigned or unassigned from teams. |
| **Schedule** | Run daily, weekly, hourly, or at a defined time. |
| **Webhook** | Let another system trigger ERPLite. |

## Condition Types

Conditions decide whether an automation or action block should run.

| Condition Type | Best For |
|----------------|----------|
| **Builder conditions** | Business-friendly field checks without code. |
| **Expression conditions** | More advanced logic using available variables. |
| **REST API validation** | Checking an external system before continuing. |
| **Managed field guards** | Conditional field rules generated from column settings. |

## Action Types

| Action | Use It For |
|--------|------------|
| **Create Record** | Create a linked or follow-up record. |
| **Update Record** | Change a field or status on an existing record. |
| **Delete Record** | Remove records when the business rule allows it. |
| **Search Records** | Find records to use in later steps. |
| **Send Email** | Notify users, vendors, customers, or internal teams. |
| **Send Slack Message** | Post operational messages to Slack channels. |
| **Call REST API** | Integrate with external systems. |
| **Code** | Handle custom logic when the structured actions are not enough. |

## Recipe Templates

The automation builder includes templates such as:

- Notify on status change.
- Assign team based on a field.
- Create a linked record.
- Require approval above an amount threshold.
- Run an overdue check on a schedule.

Templates should be treated as starting points. The AI or administrator must fill in the actual table, fields, users, teams, message content, thresholds, and verification checks.

## AI Guidance

### When to Use This Feature

An AI should use automation only after identifying:

- The trigger event.
- The condition that decides whether it should run.
- The action that should happen.
- The proof that the action happened.
- The owner who should be alerted if it fails.

If the request is "guide a user through a status change", use a workflow action. If the request is "do something after the status change", use an automation.

### How to Use It

<Steps>
  <Step title="Name the automation">
    Use a name that explains the business outcome, such as **Notify manager when PO exceeds approval limit**.
  </Step>
  <Step title="Choose the trigger">
    Pick record created, record updated, schedule, webhook, or account event.
  </Step>
  <Step title="Add conditions">
    Use field conditions to narrow when the automation runs. Avoid running on every update unless that is truly intended.
  </Step>
  <Step title="Add action blocks">
    Group related actions together and add block-level conditions where needed.
  </Step>
  <Step title="Configure actions">
    Choose table actions, email, Slack, REST API, search, delete, or code.
  </Step>
  <Step title="Test with sample data">
    Use real-looking sample records and users. Check the test output before activating.
  </Step>
  <Step title="Activate and monitor">
    Turn on the automation and verify the first live run.
  </Step>
</Steps>

### How to Verify

The AI should verify:

- The automation does not run for records that do not match the condition.
- The automation runs for records that do match.
- The expected record update, new record, message, Slack post, document, or external API result happens.
- Dynamic values in messages are correct.
- Secret keys or account integrations are configured before actions depend on them.
- Failure messages are visible enough for an administrator to diagnose.
- Scheduled automations use the account's intended timezone.

## Verification Examples

| Automation | Verification |
|------------|--------------|
| Notify when PO is confirmed | Confirm a sample PO and check the email/Slack message content. |
| Create dispatch from sales order | Move a sample SO to the trigger status and confirm a dispatch draft appears with correct line items. |
| Daily overdue check | Use an overdue sample record and confirm the scheduled check finds it. |
| Update parent status from child records | Edit child records and confirm the parent status or rollup changes. |
| External API call | Confirm the external system received the request and ERPLite shows the expected result. |

<Warning>
Automations can change many records quickly. Test on a small sample before enabling a broad update, delete, or external API action.
</Warning>
