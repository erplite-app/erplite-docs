title: API Keys and Secrets

Use **Settings > API Keys & Secrets** to manage credentials that automations and integrations need. This keeps sensitive values out of table fields and workflow notes.

## ERPLite API Key

The **ERPLite API Key** is the managed key used by ERPLite automation scripts and integrations that need authenticated access back into your workspace.

You can:

- Generate the key if it has not been configured yet.
- Copy the current key when setting up a trusted integration.
- Regenerate the key when you need to rotate credentials.

<Warning>
Regenerating the ERPLite API Key immediately invalidates the previous key. Update any integration still using the old key before or immediately after rotation.
</Warning>

## Other Secrets

Other secrets are used for third-party systems such as payment gateways, messaging tools, CRMs, ERPs, or internal APIs.

Each secret has:

| Field | Description |
|-------|-------------|
| **Key Identifier** | A stable name used by automations to reference the secret. Use letters, numbers, underscores, or hyphens. |
| **Display Name** | A human-readable name administrators can recognize. |
| **Secret Value** | The actual credential or token. |

## Add a Secret

<Steps>
  <Step title="Open API Keys & Secrets">
    Go to **Settings > API Keys & Secrets**.
  </Step>
  <Step title="Click Add Secret">
    Enter a key identifier and display name.
  </Step>
  <Step title="Paste the secret value">
    Store the credential exactly as provided by the external system.
  </Step>
  <Step title="Save">
    The secret becomes available to automations.
  </Step>
</Steps>

## Update a Secret

Use **Update value** when a third-party key rotates. The identifier stays the same so automations do not need to be rebuilt.

## Best Practices

- Use clear identifiers, such as `stripe_api_key`, `warehouse_api_token`, or `slack_webhook`.
- Rotate secrets on a schedule that matches your company's security policy.
- Limit who can access this page.
- Remove secrets that are no longer used by active automations or integrations.

## AI Guidance

### When to Use This Feature

An AI should use API Keys and Secrets when automations, document generation, integrations, or external API calls need credentials.

### How to Use It

1. Identify the integration that needs a secret.
2. Store the credential with a clear identifier.
3. Configure the automation or integration to reference that secret.
4. Rotate keys carefully when needed.

### How to Verify

The AI should verify that the dependent automation or integration succeeds and that regenerating a key does not break active processes unexpectedly.
