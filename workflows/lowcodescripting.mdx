Most ERPLite setup should use structured features: tables, relations, derived fields, conditional rules, workflow buttons, and automation actions. Custom logic is for cases where the business rule cannot be expressed clearly with those tools.

## When to Use Custom Logic

Use custom logic for:

- Complex calculations that derived fields cannot express.
- Integration payloads that require custom formatting.
- Multi-step checks across several related records.
- Business rules that need custom branching.

Avoid custom logic for simple field updates, notifications, record creation, lookups, rollups, or status changes. Those should use built-in configuration first.

## AI Guidance

### When to Use This Feature

An AI should choose custom logic only after explaining why structured configuration is not sufficient.

### How to Use It

1. Write the business rule in plain language.
2. Identify the input data the logic needs.
3. Identify the expected output or side effect.
4. Test with realistic sample data.
5. Capture the reason this was not implemented with built-in actions.

### How to Verify

The AI should verify:

- The logic succeeds with normal data.
- The logic fails safely with missing or unexpected data.
- The output matches the business rule.
- Any external calls or secret keys are configured.
- A business owner can understand what the custom logic is supposed to do.
