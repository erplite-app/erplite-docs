A workflow defines how a record moves through a business process. In ERPLite, workflows are usually attached to a table status field. They control the visible status bar, the action buttons users can click, and the rules that decide when each action is allowed.

Examples:

- Purchase Order: Draft → Confirmed → Sent to Vendor → Received → Closed
- Sales Order: New → Ready → In Production → Packed → Dispatched → Delivered
- Work Order: Open → In Progress → Waiting for Parts → Completed
- Approval: Draft → Submitted → Approved or Rejected

## What a Workflow Contains

| Part | Purpose |
|------|---------|
| **Status field** | The dropdown/status column that stores the record's current stage. |
| **Start status** | The status assigned to new records. |
| **Happy path** | The main expected path shown in the status bar. |
| **Transitions** | Buttons that move a record from one status to another. |
| **Actions** | Buttons that run an automation without changing status. |
| **Links** | Buttons that open a useful URL or external page. |
| **Visibility rules** | Conditions that decide whether a button is available. |
| **Confirmations** | Prompts shown before risky or destructive actions. |
| **Validation issues** | Warnings when the status field or options no longer match the workflow. |

## AI Guidance

### When to Use This Feature

An AI should use a workflow when the business describes stages, approvals, handoffs, button actions, or process guardrails.

Use a workflow when users need to answer:

- What stage is this record in?
- What can I do next?
- Who should take the next action?
- What should be blocked until required information is present?

Do not use a workflow only to categorize records. If users do not need stage-specific actions, a simple status dropdown and saved views may be enough.

### How to Use It

<Steps>
  <Step title="Choose the table">
    Identify the table whose records move through the process.
  </Step>
  <Step title="Choose or create the status field">
    Use a single-select status/dropdown field with all business stages.
  </Step>
  <Step title="Set the start status">
    Decide the first status for new records.
  </Step>
  <Step title="Declare the happy path">
    Arrange the main statuses in the order users expect to see them.
  </Step>
  <Step title="Add transitions">
    Add buttons that move records between statuses.
  </Step>
  <Step title="Add guards and visibility rules">
    Hide or block actions when records are missing required business conditions.
  </Step>
  <Step title="Add actions and links">
    Add automation buttons and external links where users need them.
  </Step>
  <Step title="Save and test">
    Run a sample record through the workflow.
  </Step>
</Steps>

### How to Verify

The AI should verify:

- New records start in the configured start status.
- The status bar shows the intended happy path.
- Forward, revert, and exit actions are displayed clearly.
- Buttons appear only when their visibility rules allow them.
- Confirmations appear for risky transitions.
- Status changes persist after refresh.
- Views and reports that depend on status update after actions.
- Workflow validation does not show missing status fields or missing status options.

<Warning>
Do not rename or remove status options without checking workflows. Transitions, start status, and happy path stages depend on those values.
</Warning>
