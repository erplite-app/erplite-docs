Transitions are workflow buttons that move a record from one status to another. Workflows can also include actions that run automations without changing status, and links that open another page or system.

## Button Types

| Type | What It Does | Example |
|------|--------------|---------|
| **Transition** | Changes the record's status. | Confirm PO, Mark Received, Complete Work Order. |
| **Action** | Runs an automation without status change. | Generate Document, Send Reminder, Recalculate. |
| **Link** | Opens an internal or external URL. | Open ERP Order, View Vendor Portal. |

## Transition Design

Each transition should have:

- A clear button label.
- A from-status.
- A to-status.
- Optional visibility rules.
- Optional confirmation copy.
- Optional automation attached to the transition.

## AI Guidance

### When to Use This Feature

An AI should add a transition when the business describes a deliberate user action that changes the stage of a record.

Use an action instead when the user should run work but the status should stay the same.

Use a link when ERPLite should send the user to another page or external system rather than performing a data change.

### How to Use It

<Steps>
  <Step title="Select the workflow">
    Open the workflow for the table.
  </Step>
  <Step title="Add a transition, action, or link">
    Use **Add > Transition**, **Add > Action**, or **Add > Link**.
  </Step>
  <Step title="Configure the label">
    Use business language users recognize, such as **Approve**, **Dispatch**, or **Mark Received**.
  </Step>
  <Step title="Set source and target status">
    For transitions, choose where the button appears and which status it moves to.
  </Step>
  <Step title="Add conditions">
    Add visibility or guard rules if the action should only appear for some records or users.
  </Step>
  <Step title="Add confirmation where needed">
    Use confirmations for irreversible, destructive, or exception actions.
  </Step>
</Steps>

### How to Verify

The AI should verify:

- The button appears on records in the correct from-status.
- The button is hidden when conditions are not met.
- Clicking the button changes status or runs the action as intended.
- Confirmation text is clear and appears only where needed.
- Related automations run after the action if configured.
- The record refreshes and shows the new status/action result.

## Good Button Labels

| Weak Label | Better Label |
|------------|--------------|
| Submit | Submit for Approval |
| Done | Mark Work Order Complete |
| Next | Move to Production |
| Send | Send PO to Vendor |
| Reject | Reject with Reason |
