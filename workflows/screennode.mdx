Screens are the user-facing forms and layouts where work gets done. In table-driven ERPLite setups, screens usually correspond to create forms, record detail pages, and related record tabs.

## Good Screen Design

- Show only fields needed for the current task.
- Use sections or tabs for complex records.
- Put decision-driving fields near the top.
- Hide read-only system fields unless they help the user.
- Use conditional fields to keep forms short.
- Use relations and inline child tables for line items.

## AI Guidance

### When to Use This Feature

An AI should adjust screens when users say a form is confusing, too long, missing fields, or showing fields at the wrong time.

### How to Use It

1. Identify the user role and task.
2. List the fields required for that step.
3. Hide, lock, or require fields conditionally.
4. Put related child records in tabs or inline tables.
5. Test with a real user scenario.

### How to Verify

The AI should verify:

- Users can complete the step without unrelated fields.
- Required fields are obvious.
- Conditional fields appear only when needed.
- Target users can complete the screen from the supported ERPLite dashboard experience.
