Workflow testing proves that users can move records through the intended business process and that blocked actions are blocked for the right reasons.

## Test Before Rollout

Test every workflow with at least:

- One happy-path record.
- One record missing required information.
- One record that should take an exception path.
- One user who should have access.
- One user who should not have access.

## AI Guidance

### When to Use This Feature

An AI should test workflows after creating or editing statuses, transitions, actions, guards, confirmations, permissions, automations, or status-based views.

### How to Use It

<Steps>
  <Step title="Create sample records">
    Create records that represent normal, invalid, and exception scenarios.
  </Step>
  <Step title="Run the happy path">
    Move one record through every expected stage from start to completion.
  </Step>
  <Step title="Test blocked actions">
    Try to run transitions when required fields, dates, approvals, or relations are missing.
  </Step>
  <Step title="Test permissions">
    Confirm buttons appear only for users who should use them.
  </Step>
  <Step title="Test side effects">
    Confirm automations, generated documents, related records, reports, and home widgets update.
  </Step>
</Steps>

### How to Verify

The AI should produce a short test summary that includes:

- Test record names or IDs.
- Starting and ending status for each path.
- Buttons tested.
- Guards that blocked correctly.
- Automations that ran.
- Reports/views checked after status changes.
- Any assumptions or unresolved business decisions.

## Acceptance Checklist

- New records start in the correct status.
- Happy-path status bar is correct.
- Each transition has a clear label.
- Required business data is enforced before the transition.
- Users cannot skip restricted stages.
- Exception paths are available only when intended.
- Status-based views update after transitions.
- Reports and home widgets reflect changed records.
