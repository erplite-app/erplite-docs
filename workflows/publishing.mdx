Publishing means the workflow is ready for users to rely on. Before publishing or treating a workflow as live, confirm that the table, status field, permissions, views, automations, reports, and user training are aligned.

## Pre-Publish Checklist

- Status field exists and is single-select.
- Start status is valid.
- Happy path is declared.
- All transitions reference current status options.
- Buttons have clear labels.
- Guards and visibility rules are tested.
- Risky actions have confirmation copy.
- Required automations are active.
- Daily views exist for each team.
- Permissions are tested with real user roles.
- Reports and home widgets are updated.

## AI Guidance

### When to Use This Feature

An AI should use this checklist whenever workflow changes affect live users, especially if a status option, transition, automation, or permission changed.

### How to Use It

1. Run the workflow testing checklist.
2. Review validation warnings in the workflow builder.
3. Confirm the business owner approves the status path and button labels.
4. Confirm affected users have access.
5. Confirm related automations are active and tested.
6. Capture a handoff note with what changed and how it was verified.

### How to Verify

The AI should verify:

- A live or sample user can execute the workflow in the table UI.
- No workflow validation issue points to a missing field or missing option.
- All status-based views still work.
- Existing records in old statuses have a path forward.
- Rollback or correction steps are known if a transition is configured incorrectly.

<Tip>
For major workflow changes, publish during a low-risk window and monitor the first few real records.
</Tip>
