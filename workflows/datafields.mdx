Workflow data fields are the values a process uses while users complete work. In table-driven workflows, most workflow data comes from table columns and related records.

## Field Sources

| Source | Examples |
|--------|----------|
| **Record fields** | Status, owner, amount, due date, priority, location. |
| **Related records** | Vendor, customer, asset, line items, dispatches, invoices. |
| **System fields** | Created date, updated date, created by, current user, current team. |
| **Derived fields** | Totals, lookups, rollups, calculated values. |
| **Automation context** | Previous value, current value, webhook payload, scheduled run time. |

## AI Guidance

### When to Use This Feature

An AI should review data fields whenever it configures workflow actions, guards, validations, automations, reports, or dashboard widgets.

### How to Use It

1. List the fields required to make the business decision.
2. Confirm each field exists on the table or related record.
3. Create missing fields using the correct column type.
4. Use derived fields for values that should be calculated.
5. Use conditional fields or validations when a field is required only in some statuses.

### How to Verify

The AI should verify:

- Every workflow rule references an existing field.
- The field type matches the rule being applied.
- Required fields are visible to the users who must fill them.
- Restricted fields are still available to automations only where appropriate.
