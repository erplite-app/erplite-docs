Action blocks group actions that should run together. Each block can have its own conditions, so an automation can branch into different outcomes without becoming hard to read.

## When to Use Action Blocks

Use action blocks when:

- Different actions should run for different statuses.
- One set of actions is for managers and another is for operators.
- You need an approval path and a rejection path.
- A notification should run only when a threshold is crossed.
- Multiple actions should share the same condition.

## AI Guidance

### When to Use This Feature

An AI should use action blocks when a single automation has more than one outcome or when several actions share the same condition.

### How to Use It

<Steps>
  <Step title="Name the block">
    Use a business name such as **Over threshold**, **Notify vendor**, or **Create dispatch records**.
  </Step>
  <Step title="Add block conditions">
    Configure when the block should run.
  </Step>
  <Step title="Add actions">
    Add record updates, record creation, search, email, Slack, REST API, or code actions.
  </Step>
  <Step title="Order actions carefully">
    Put actions in the order the business outcome requires.
  </Step>
</Steps>

### How to Verify

The AI should verify:

- The block runs only when its conditions are true.
- Each action in the block completes.
- Action order does not create incorrect data.
- Failure in one action is visible and does not silently hide the issue.
