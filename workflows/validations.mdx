Validations and guards prevent users or automations from moving bad data forward. They should explain what is wrong and what the user needs to fix.

## Common Validation Examples

| Business Rule | Validation |
|---------------|------------|
| PO cannot be confirmed without expected delivery date | Block Confirm unless Expected Delivery Date is filled and in the future. |
| Dispatch cannot be created for cancelled sales order | Hide or block Dispatch action when Sales Order status is Cancelled. |
| Amount above threshold needs approval | Require approval status or approver before moving forward. |
| Rejection needs reason | Require Rejection Reason when Decision is Rejected. |
| Inventory cannot go negative | Block update when requested quantity exceeds available stock. |

## AI Guidance

### When to Use This Feature

An AI should add a validation when the business says:

- "Do not allow..."
- "Must not proceed unless..."
- "Require..."
- "Block..."
- "Only managers can..."
- "This action is invalid when..."

### How to Use It

<Steps>
  <Step title="Write the rule in plain language">
    Example: "Users cannot confirm a PO unless Expected Delivery Date is in the future."
  </Step>
  <Step title="Choose where to enforce it">
    Use conditional field rules for field-level behavior, workflow guards for action buttons, and automations for broader business checks.
  </Step>
  <Step title="Configure the condition">
    Use field values, status, user, team, dates, or related records.
  </Step>
  <Step title="Add a clear message">
    Tell the user exactly what to fix.
  </Step>
  <Step title="Test passing and failing records">
    Verify the rule blocks invalid records and allows valid records.
  </Step>
</Steps>

### How to Verify

The AI should verify:

- Invalid records are blocked.
- Valid records pass.
- The error message is business-friendly.
- The rule works after refresh and for users with different roles.
- Imports, automations, and AI-driven changes cannot bypass enforced field rules.

<Tip>
Every validation should have a positive test and a negative test. If only one side is tested, the rule is not proven.
</Tip>
