Workflow automations run alongside workflow actions. They are useful when clicking a workflow button should do more than change a status.

Examples:

- Send an approval email when a record is submitted.
- Generate a document when a PO is confirmed.
- Update inventory when a dispatch is marked delivered.
- Notify a manager when an exception path is used.
- Create follow-up records after a status change.

## When to Use Workflow Automations

Use workflow automations when a user action should trigger a repeatable side effect.

Use table automations when the trigger is simply a record being created, updated, deleted, scheduled, or received by webhook.

## AI Guidance

### When to Use This Feature

An AI should use workflow automation when the business says "when the user clicks this button, also do this other thing."

### How to Use It

<Steps>
  <Step title="Identify the workflow action">
    Choose the transition or action button that should trigger the automation.
  </Step>
  <Step title="Define the side effect">
    Decide whether the automation sends a message, updates a record, creates a record, generates a document, or calls another system.
  </Step>
  <Step title="Add conditions if needed">
    Add conditions so the automation runs only for the correct records.
  </Step>
  <Step title="Test the button">
    Click the workflow button on a sample record and confirm both the status/action and automation result.
  </Step>
</Steps>

### How to Verify

The AI should verify:

- The workflow action still completes.
- The automation runs only after the intended button is used.
- Messages, documents, related records, or external calls contain the correct data.
- Failures are visible to an administrator.
